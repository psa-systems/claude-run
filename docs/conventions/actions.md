# Actions

Full text of the `CLAUDE.md` conventions on this topic, moved there verbatim by CLAUDE-370. The index in `CLAUDE.md` links each heading below.

## Reporting actions (CLAUDE-218, CLAUDE-215)

Not every action works code. `closed-issue-summary.yml` (`kind: closed-issue-summary`, `src/native/closed_issue_summary.rs`, CLAUDE-218) is the runner used as a REPORTING tool: it counts and lists the issues closed in a rolling window across a project list, files that report as a new issue, and links it to a nominated parent as a subtask. It clones no repository, starts no agent session, and opens no pull request. It is partitioned off `youtrack.yml` on the `AI Agent` axis (the worker pins `Queued`; a reporting `query` must pin its own value), the same "one action, one job" split CLAUDE-215 made for audits on the project and tag axes (`audit-run.yml` selects `project: {{audit_project}} tag: Audit-*`, `youtrack.yml` its complement `(project: -{{audit_project}} or tag: -Audit-*)`; both substitute `native.youtrack.audit_project`, default `AUDIT`, CLAUDE-409). `shipped_action_queries_are_disjoint` in `src/action.rs` guards the partition; `youtrack.yml` deliberately writes no negation, because YouTrack 400s a query naming an `AI Agent` value that is not in the bundle.

## Audited YouTrack writes (CLAUDE-234)

Every YouTrack write the runner makes goes through one run-scoped wrapper (CLAUDE-234): `provider::AuditedTracker`, built per run from `provider::IssueWriteAudit` and wrapped around whichever `IssueTracker` the run resolved. It does two things the prompt cannot be trusted to do: it spends one slot of `limits.max_issues_per_run` (default 25, `provider::DEFAULT_MAX_ISSUES_PER_RUN`) per `create_issue` and refuses past the ceiling BEFORE `yt issue create` is invoked, and it journals one `youtrack issue write` line per create and per update carrying the run id and the issue key. A refusal is a typed `Error::IssueCapReached`, a `warn`, and a `run_events` row on the run, so a truncated filing run never reads as clean. The ledger is per RUN, not per backend: the youtrack action builds a backend per job and the webhook mint backend is daemon-lifetime, so a counter held on the backend would be wrong in both directions. Deletes stay denied by omission (the trait exposes none) and `no_delete_on_the_tracker_surface` fails if one reappears. The cap covers the runner's own provider calls, not the `yt` calls an agent session makes inside its workdir.

## Run-comment footer (CLAUDE-446)

Every comment the runner itself posts to an issue (never a human's) carries a trailing footer, built by `crate::run_footer` and appended at the call site, not inside `IssueTracker::comment` or `AuditedTracker`: the footer needs the caller's own run id and timing, which the tracker layer does not have. `append_job` is for a job-lifecycle comment (`finalize`'s six outcomes, the dependency gate's blocker comment inside a job, a PR-record/salvage-clear failure note) and links `/runs/<id>/jobs/<key>/attempt/<n>` using the `CommentRun` the job loop threads in; `append_run` is for everything else (automerge, the CI-webhook triage/mint paths, the closed-issue summary, the restart reconcile) and links `/runs/<id>`, or says the link is unavailable when `CLAUDE_RUN_PUBLIC_URL` is unset, or says no run id is available when the comment is not tied to one run row (the restart reconcile; a run that never opened a row). Both read `crate::run_footer::resolved_public_url()`, never `crate::config::public_url()` directly, so a malformed `CLAUDE_RUN_PUBLIC_URL` degrades a comment's footer instead of failing the comment. The footer's `Started`/`Finished` timestamps are wall-clock and therefore not byte-stable between two runs of the same scenario; a test comparing two call traces for structural equality (`webhook_and_reconciler_agree_on_every_decision_shape`) strips everything from `\nStarted: ` onward before comparing, and a test stubbing an exact `yt issue comment` invocation uses `testutil::StubRunner::ok_prefix` instead of `ok`, matching on everything up to the footer rather than the exact, time-dependent body.
