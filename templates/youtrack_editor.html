Automerge

When enabled, a successful run still stops at Code Review. The runner merges the PR later, once its CI goes green and the branch is mergeable, then comments on the issue; AI Agent and State stay at Code Review, and a YouTrack workflow (see docs/yt-workflow-resolve-on-pr-merge.js) resolves the issue once the merge lands. Normally the merge happens within seconds of a Forgejo Action Run Success or Recover webhook; if that webhook is missed, dropped, or never configured, a periodic reconciler pass merges it within a few minutes instead, so the webhook is a low-latency trigger and not a requirement (see "Event-driven automerge" in docs/webhooks.md). Disabled (the default) leaves the PR for a human to merge.

Comma-separated project keys the agent may create issues in when filing a gap, deferred item, or out-of-scope bug. Blank resolves to the triggering issue's own project. The no-code label is the AI Agent value set when a run deliberately produces no commits; blank inherits the Done label above. The Needs-Info tag is attached alongside the Needs review AI Agent value only when the agent parks an issue pending a human answer (not on an attempt-cap or timeout park); blank writes no tag.
